## How the orchestrator picks the next task

Deterministic rules (apply in order):

### 1. Source of truth

Only tasks in [docs/tensor-clone-epics.md](docs/tensor-clone-epics.md) with `Status: TODO` are eligible. Ignore `DONE` and policy rows marked complete.

### 2. Dependency gate

A task is **eligible** when every ID in its **Deps** column is `DONE` (or `—`).  
If Deps reference an epic (e.g. `TC-EP-API`), all **P0 tasks** in that epic that block the current week must be done first (see week rollup in epics doc).

### 3. Priority stack

Among eligible tasks, pick the **lowest** priority band first:

| Band | Rule |
|------|------|
| **A — Unblockers** | Ops/env tasks that unblock others: `TC-055`, `TC-061`, `TC-066` |
| **B — Current week** | Tasks in active week column (see § Week pointer below) |
| **C — P0 UX/API** | Collection grid live (`TC-020`), venue (`TC-024`), buy modal (`TC-037`) |
| **D — Parallel epics** | Tasks with **∥ = Y** and no file conflict with in-flight work |
| **E — Everything else** | By ascending `TC-NNN` |

### 4. Parallel vs serial

- **∥ = N** on a task: do not start another **∥ = N** task in the same epic until it merges (avoids `tensor-tcm.ts` / API route conflicts).
- **∥ = Y**: may run alongside other Y tasks if Deps satisfied (e.g. `TC-119` perf while `TC-052` BFF in parallel).

### 5. Human overrides

Edit **Next queue** below to force order. Overrides win over rules 3–4 until cleared.

### 6. After completing a task

1. Set task `DONE` in [docs/tensor-clone-epics.md](docs/tensor-clone-epics.md).  
2. Update epic row to `PARTIAL` or `DONE` if all child tasks complete.  
3. Refresh **Next queue** (run rules 1–4 or `npm run status:next` when script exists).  
4. Mirror major milestones in [docs/mvp-backlog.md](docs/mvp-backlog.md) (`P2-INT-T06` … `T20`) if applicable.
